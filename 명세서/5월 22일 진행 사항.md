# 5월 22일 진행 사항

## 1. Igris Boss Skill_10 다단 장판 판정

### 목표

`Skill_10_Start/Loop/End` 를 단순 타이머 기반 장판이 아니라, 애니메이션 Notify 흐름에 맞춘 다단 동심원 패턴으로 정리한다.

- 1타: 보스 중심 작은 원 `0 ~ R1`
- 2타: 첫 번째 링 `R1 ~ R2`
- 3타: 두 번째 링 `R2 ~ R3`
- 4타: 전체 원 `0 ~ R3`

피격 판정은 바닥 이펙트와 분리한다. 바닥에는 원/링이 차오르는 시각 표현을 두고, 실제 판정은 `XZ 거리 + Y 높이 제한` 기반 수학 판정으로 처리한다.

## 2. Skill_10 Notify 설계 확정

### 애니메이션 길이와 Notify 배치

| 클립 | 길이 | Notify |
| --- | ---: | --- |
| `Skill_10_Start` | 약 `1.4s` | `1.2s ATTACK_HITBOX_ON` |
| `Skill_10_Loop` | 약 `0.7s` | `0.2s ATTACK_HITBOX_ON`, `0.6s ATTACK_HITBOX_OFF` |
| `Skill_10_End` | 약 `2.4s` | `0.8s ATTACK_HITBOX_OFF` |

### 최종 흐름

```text
Start(0)
  ON  -> 1타 작은 원 fill 시작

Loop(0)
  ON  -> pending 유지
  OFF -> 데미지 스킵, combo 0 -> 1

Loop(1)
  ON  -> pending 유지
  OFF -> 1타 데미지, combo 1 -> 2

Loop(2)
  ON  -> 2타 링 fill 시작
  OFF -> 2타 데미지, combo 2 -> 3

Loop(3)
  ON  -> 3타 링 fill 시작
  OFF -> 3타 데미지, combo 3 -> 4

Loop(4)
  ON  -> 4타 전체 원 fill 시작, End 전환

End(4)
  OFF -> 4타 데미지, reset
```

### 설계 의도

- 1타가 `Loop` 진입 직후 바로 터지는 문제를 피하기 위해 `Loop(0)` 을 예고 유지 구간으로 둔다.
- `Skill_10_Loop` 는 짧은 클립이므로 여러 Notify 세트를 넣지 않고 `ON + OFF` 한 세트만 둔다.
- `m_iSkill10AreaCombo` 값으로 현재 단계의 의미를 해석한다.
- `ON` 은 pending Area 시작, `OFF` 는 pending Area 확정 데미지로 본다.
- `Skill_10` 에서는 `ATTACK_HITBOX_ON/OFF` 가 무기 hitbox 토글이 아니라 장판 fill/resolve 신호다.

## 4. Skill_10 Loop 재시작 정책

`Skill_10_Loop` 는 같은 상태로 재진입해야 하므로 `StateMachine::Try_Action(SKILL_10, LOOP)` 만으로는 부족하다.

현재 `CStateMachine::Try_Transition()` 은 같은 상태 요청 시 바로 `true` 를 반환하므로 `On_Transition()` 과 `Body::Play_Action()` 이 호출되지 않는다.

따라서 Loop 클립 반복은 아래 정책을 따른다.

- `Skill_10_Loop` 바인딩의 `bRestartOnEnter = true`
- 같은 Loop 재생은 `m_pBody->Play_Action(SKILL_10, LOOP, COMMON)` 직접 호출
- `Skill_10` 시작/종료 시에만 combo reset
- Loop 재생마다 combo 를 reset하지 않음

## 5. RootMotion override 원인 확인

`Skill_10_Start/Loop/End` 의 에디터 RootMotion 설정이 런타임에서 반영되지 않는 원인을 확인했다.

문제는 `MonsterAnimTable.cpp` 의 바인딩에서 아래처럼 RootMotion 을 강제로 끄고 있었던 것.

```cpp
{ MONSTER_ACTION::SKILL_10, ..., "Skill_10_Start", true, true, false, true, false },
{ MONSTER_ACTION::SKILL_10, ..., "Skill_10_Loop",  true, true, true,  true, false },
{ MONSTER_ACTION::SKILL_10, ..., "Skill_10_End",   true, true, false, true, false },
```

뒤쪽 두 값의 의미:

```cpp
bOverrideRootMotion = true
bUseRootMotion = false
```

즉 에디터에서 RootMotion 을 켜도 `CBody_Monster::Register_AnimationClips()` 에서 false 로 다시 덮었다.

### 권장 수정

에디터 저장값을 따르게 하려면 RootMotion override 인자를 제거한다.

```cpp
{ MONSTER_ACTION::SKILL_10, MONSTER_PHASE::COMMON, MONSTER_ACTION_STEP::START, "Skill_10_Start", true, true, false },
{ MONSTER_ACTION::SKILL_10, MONSTER_PHASE::COMMON, MONSTER_ACTION_STEP::LOOP,  "Skill_10_Loop",  true, true, true },
{ MONSTER_ACTION::SKILL_10, MONSTER_PHASE::COMMON, MONSTER_ACTION_STEP::END,   "Skill_10_End",   true, true, false },
```

이렇게 하면 Loop 여부만 코드에서 강제하고, RootMotion 은 `.bin`/에디터 메타를 따른다.

### 11.2 `Client/Private/Player.cpp`

#### (1) `Enable_SkillCollider` — 진입 시 hit set reset

```cpp
void CPlayer::Enable_SkillCollider(_bool bEnable)
{
    if (true == bEnable && false == m_bSkillColliderActive)
        m_SkillHitTargets.clear();   // R6-C: spawn 마다 새 타격 윈도우

    m_bSkillColliderActive = bEnable;
}
```

#### (2) `On_SkillColliderHit` — Loop 컨텍스트 damage 분기 추가

```cpp
void CPlayer::On_SkillColliderHit(CCollider* pOther)
{
    if (false == m_bSkillColliderActive)
        return;
    if (nullptr == m_pStateMachine || nullptr == pOther)
        return;

    // R6-B: SKILL_F + START + KnightKiller — 즉시 Start→Loop 전이 (damage X)
    if (true == Is_SkillF_KnightKiller_Start())
    {
        m_pStateMachine->Try_Action_External(
            CHARACTER_ACTION::SKILL_F, CHARACTER_ACTION_STEP::LOOP);

        Enable_SkillCollider(false);
        return;
    }

    // R6-C: SKILL_F + LOOP + KnightKiller — sphere damage 부여
    if (true == Is_SkillF_KnightKiller_Loop())
    {
        if (COLLISION_GROUP::MONSTER_BODY != pOther->Get_Group())
            return;

        CGameObject* pTarget = pOther->Get_Owner();
        if (nullptr == pTarget)
            return;

        if (m_SkillHitTargets.end() != m_SkillHitTargets.find(pTarget))
            return;
        m_SkillHitTargets.insert(pTarget);

        CMonster* pMonster = dynamic_cast<CMonster*>(pTarget);
        if (nullptr == pMonster)
            return;

        pMonster->Take_Damage(m_fSkillColliderDamage);
        return;
    }
}
```

#### (3) `Is_SkillF_KnightKiller_Loop` 신규

```cpp
_bool CPlayer::Is_SkillF_KnightKiller_Loop() const
{
    if (nullptr == m_pStateMachine)
        return false;

    return (CHARACTER_ACTION::SKILL_F == m_pStateMachine->Get_CurrentCharacterAction()
        && CHARACTER_ACTION_STEP::LOOP == m_pStateMachine->Get_CurrentCharacterStep()
        && EQUIPPED_WEAPON_ID::KNIGHT_KILLER == m_eEquippedWeapon);
}
```

### 11.3 `Client/Private/Player_StateMachine.cpp`

`ATTACK_HITBOX_ON / OFF` 분기 (418~424) 를 컨텍스트 dispatch 형태로 확장:

```cpp
case ANIM_NOTIFY_TYPE::ATTACK_HITBOX_ON:
{
    // R6-C: SKILL_F + LOOP + KnightKiller 컨텍스트면 weapon OBB 대신 sphere 토글
    if (nullptr != m_pOwner
        && CHARACTER_ACTION::SKILL_F == Get_CurrentCharacterAction()
        && CHARACTER_ACTION_STEP::LOOP == Get_CurrentCharacterStep()
        && EQUIPPED_WEAPON_ID::KNIGHT_KILLER == m_pOwner->Get_EquippedWeapon())
    {
        m_pOwner->Enable_SkillCollider(true);
        break;
    }

    ++m_iAttackHitboxWindowSerial;
    m_bAttackHitboxActive = true;
    break;
}
case ANIM_NOTIFY_TYPE::ATTACK_HITBOX_OFF:
{
    if (nullptr != m_pOwner
        && CHARACTER_ACTION::SKILL_F == Get_CurrentCharacterAction()
        && CHARACTER_ACTION_STEP::LOOP == Get_CurrentCharacterStep()
        && EQUIPPED_WEAPON_ID::KNIGHT_KILLER == m_pOwner->Get_EquippedWeapon())
    {
        m_pOwner->Enable_SkillCollider(false);
        break;
    }

    m_bAttackHitboxActive = false;
    break;
}
```
