# 2026-05-23 진행 사항

## 1. 수업 코드 렌더 트랙 진행

### 1.1 RenderTarget / MRT / Debug Preview

- 수업 코드 11~12일차 흐름을 기준으로 `RenderTarget`, `Target_Manager`, MRT 기반 렌더 경로를 현재 프로젝트 구조에 맞춰 적용 중이다.
- 현재 확인된 MRT 구성은 `MRT_GameObjects = Diffuse / Normal / Depth`, `MRT_LightAcc = Shade / Specular` 이다.
- Debug Preview 는 `Target_Diffuse`, `Target_Normal`, `Target_Shade`, `Target_Specular` 를 좌측/상단에 16:9 비율로 배치해 확인한다.
- `Target_Diffuse`, `Target_Normal`, `Target_Shade` 는 화면에서 정상 확인되며, `Target_Specular` 는 광원/스페큘러 값에 따라 검게 보일 수 있다.

### 1.2 Deferred / LightAcc 현재 상태

- 현재 렌더 순서는 `Priority -> NonBlend -> Lights -> Combined -> NonLight -> Blend -> UI -> Debug` 흐름으로 정리되어 있다.
- `CRenderer::Render_Lights()` 에서 `Target_Normal`, `Target_Depth` 를 LightAcc 셰이더에 넘기고, `Render_Combined()` 에서 `Diffuse + Shade + Specular` 를 합성하는 구조로 확장 중이다.
- `Shader_Deferred.hlsl` 은 현재 코드 기준 수업 코드 14일차 구조에 가깝게 적용되어 있다.
  - `g_NormalTexture`, `g_DepthTexture` 기반 world position reconstruction
  - Directional Light 누적
  - Point Light range attenuation
  - Shade / Specular 분리 출력
  - `Diffuse * Shade + Specular` Combined
- 프로젝트 모델 리소스는 diffuse alpha 값이 불안정해 기존 alpha discard 로 모델이 사라질 수 있다. 따라서 Mesh/AnimMesh 쪽에서 `vMtrlDiffuse.a = 1.f` 로 보정한 상태를 유지하고, Deferred Combined 의 discard 는 수업 코드 기준을 따르되 입력 alpha 안정화를 전제로 한다.

### 1.3 ThroneRoom 조명 자료 확인

- `Fog_ThroneR_01` 에서 확인한 주요 값:

  - `sunColor = (1, 1, 1)`
  - `sunIntensity = 6.56`

  - `specularIntensity = 0.8`
  - `ambientLightMultiplier = 1.0`

- `LightingPlanPlayableAsset` 계열에서는 캐릭터 라이트 후보로 `(50, 150.8, 4.33)` 회전과 `0.8207547` 계열 light color 가 확인되었다.

### 1.4 Point Light 방향

- ThroneRoom 의 횃불/기둥/문 주변 밝기는 Hardcode 보다 Editor 또는 SceneData 기반 PointLight 배치가 적합하다.
- 1차 검증은 `Ready_Lights()` 에 PointLight 1개를 직접 추가해 Deferred PointLight 계산을 확인한다.
- 단, `Ready_Lights()` 는 `Ready_Layer_Player()` 보다 먼저 호출되므로 Player Transform 을 직접 참조할 수 없다.
- 따라서 검증용 PointLight 는 현재 로드된 `SCENE_DATA` 의 `SPAWN_TYPE::PLAYER` SpawnPoint 를 기준으로 배치한다.
- 원점 `(0, 3, 0)` 고정 배치는 플레이어 시작 위치와 멀어질 수 있어 점광원 검증용으로 부적합하다.
- 최종 구조는 맵에 직접 배치 가능한 Light Object 또는 SceneData LightData 로 확장한다.

## 3. 현재 코드 기준 적용 의도

### 3.1 유지해야 할 설계

- 수업 코드 구조를 우선한다. 함수명, enum, pass 순서, RenderTarget/MRT 흐름은 가능하면 수업 코드의 형태를 따라간다.
- 현재 프로젝트 차이로 필요한 예외만 분리한다.
  - 모델 diffuse alpha 문제 때문에 Mesh/AnimMesh 에서 `vMtrlDiffuse.a = 1.f` 보정 유지
  - ThroneRoom 은 Unity Terrain 이 아니라 `.bin` model map 이므로 Terrain 전용 구조를 그대로 적용하지 않음
  - PointLight 는 최종적으로 Hardcode 가 아니라 SceneData / Editor 배치 데이터가 SSOT
- `Render_Lights()` 는 LightAcc MRT 에 `Shade`, `Specular` 를 누적하고, `Render_Combined()` 에서 BackBuffer 로 합성한다.
- Debug Preview 는 검증용이며 최종 연출 기능이 아니다.

### 3.2 검증용 PointLight 코드 의도

- 현재 단계의 PointLight 는 "Deferred Point Light 계산이 정상인지 확인하기 위한 임시 검증 장치" 다.
- Player SpawnPoint 기준으로 두는 이유는 `Ready_Lights()` 시점에 Player 객체가 아직 생성되기 전이기 때문이다.
- 검증이 끝나면 해당 Hardcode 는 제거하고, LightData 를 SceneData 에 포함시키거나 Editor 에서 Light Object 로 배치하도록 전환한다.
